# 路线图：Skill 优化工具

> 状态：草稿（2026-10-12）。

推导轴：检查方式的三个转变——**触发**（被要求才查 → 例行自报）× **判据位置**（写在提醒里 → 落在检查里）× **人的位置**（读全量 → 只判机器判不了的那部分）。

核心原则：**凡是每次都要靠当场想起来的，都是没落到位的。**判据要落在能自动执行的地方，人的注意力只花在判断上。

## 现在

已有两件东西：一是**机械检查脚本**（能判体量是否超线、引用材料是否有一级标题、是否被主文件指到），二是**写作规范**（写与审的口径）。缺的是四种能力，都来自一次复盘提炼出的需求：

| 缺的能力 | 具体表现 |
|---|---|
| **触发** | 文档变脏不会告警。只有被人要求检查时才检查，所以「只增不减」能长期无人发现 |
| **计数** | 「同一条判断被违反第二次就升级所在层」这句话没有落脚处——没有任何地方记着某条被违反过几次 |
| **归属判定** | 哪些内容该留在主文件、哪些该沉到引用材料，这一判断每次靠当场想，没有固定问法 |
| **可核的产出** | 每次整理完靠口头汇报，没有一份「现在什么样、改了什么、怎么核」的东西留下来 |

## 阶段一：把能机械判的都变成检查

把体量、一级标题、指针、空壳、断章信号这五项判据统一进一个入口，并补两项现在没有的：**基线对比**（只报相对上一版新增的问题，存量不刷屏）和**判断计数**（把写在判断行尾的违反次数读出来，供阶段四用）。

**达成标志**：跑一次就报出「新增了哪些问题、存量还有哪些」，且跑的当时不需要我在场想任何一件事。

## 阶段二：给出一个入口，固定三层分工

一个入口跑完三层，不靠每次临时组合：

1. **机械层**（脚本）——能判的：体量、标题、指针、空壳、断章信号、判断计数。
2. **判断层**（交给能读上下文的执行者，用一份固定问法）——判不了的：某段内容属于判断还是依据、某处指代是真断裂还是本文件内的正常指代。硬要求：**误报必须写明理由**，不许盲改。
3. **复验层**（自己的脚本，不吃第一手结论）——拿基线逐个核。第一手结论与复验结论不一致时，以复验为准，并回头修机械层的误报。

**达成标志**：说一句「检查」，三层依次跑完并产出一份可核报告；报告里任何一条数字都能被第三方脚本重新算出来。

## 阶段三：例行自报

把入口挂上周期巡检，每周自己跑一次，**只报新增**。没有新增就不打扰。

**达成标志**：连续四周不需要任何人说「检查一下」，且期间报出的问题都值得看（没有靠误报刷存在感）。

## 阶段四：判断的计数与升级

判断行尾记违反次数（如 `×2`），到第二次就升级它所在的层：**写在提醒里 → 落成脚本 → 改掉环境默认值**。升级后把这条判断从文档里降级或删除，避免同一件事两处说法。

**达成标志**：出现第一条被升级的判断，且升级之后不再被违反——这是「加固」真正的验收点。

## 顺序依据

- **先能判，再省事，最后自动**：判断口径没稳定就上巡检，只会定期产出噪音，和「共识先行」是同一条道理——没被人工走过并认可的规则，自动化只是把混乱固化。
- **判断不外包**：机械能回答「有没有」，回答不了「是不是同一回事」。所以每次检查都必须有人（或读上下文的执行者）过一遍，这一步不能自动化掉；自动化的是**筛**，不是**判**。
- **升级放在最后**：计数要先有地方记，升级要先有可升级的层——顺序颠倒就会变成「写一句更强的提醒」，而提醒已经被证明拦不住。
- **产出必须可核**：报告里的每一条都要能被独立重算，否则检查结果本身就成了新的不可信来源。

## 不做

- **不做自动改写**：判断类问题只标不改，改写交给人确认。
- **不做常驻服务**：一次一跑，跑完就把结论留在报告里。
- **不把判断交给机器**：归属、断裂真伪这类问题，机器只负责筛出候选。
- **不新增更多提醒**：同一条判断第二次出现时，动作是升级所在层，不是再写一遍。
